# 宿主兼容与本地测试

当前插件版本为 0.2.1，宿主支持范围以 `package.json` 的 `engines.dsh` 为准：仅 `0.2.2-rc.3 || 0.2.3-alpha.2`。预发布版本采用明确枚举，不通过 `>=0.2.2` 等范围推断未来版本。

## 适配边界

- `compat/dsh.js`：Cordis 服务、会话头与历史读取、会话创建和分支包装、原生开场白事件与回合计数、输入事件、提示词和工具注册。
- `compat/routes.js`：HTTP 鉴权差异。rc.3 调用宿主的 `requestRejection`；alpha.2 使用 WebServer 已鉴权的 owner Peer。未知鉴权接口拒绝注册；没有 owner Peer 时拒绝访问。路由注册通过 Cordis effect 持有清理函数，禁用或卸载时注销，避免重新启用报重复路由。
- `index.js`：持有插件数据、默认卡与会话快照，构造业务提示词，提供卡片和词条操作。适配层不拥有或迁移卡片数据。
- `client.js`：两个已测版本共用同一套模块加载和设置插槽。未来前端 API 发生变化时再新增对应适配，不复制业务页面。

两版的原生开场白协议目前一致，因此共用实现，不为版本号创建两份相同代码。只有证实协议不同才增加分支。缺少维护接口或 controller 方法时会记录告警；这不等于对未知宿主提供完整功能保证。

新增宿主版本时先核对 Cordis/DSH peer、鉴权、会话事件及生命周期，修改适配层，再运行该版和已有版本的同一套测试。验证通过后才更新兼容声明。宿主包保持 peer，避免把核心服务的另一套实例作为插件普通依赖安装。

## 测试环境

每版使用独立运行时目录、锁文件、DSH_HOME 和 profile；桌面另隔离 Electron userData/sessionData。只换 profile 不能隔离共享会话和 Home 配置。测试 Home 不复制日常凭据或会话。

正式插件源码只在本仓库修改。测试运行时和产物放仓库外，建议使用本机短路径。示例环境位于 `D:/dsh-roleplay-tests`；它是测试环境，不是项目源码的新位置。不要从一个盘复制 pnpm 的已安装 profile 到另一个盘后直接使用，应在目标测试 Home 重新安装，以免 store 路径不一致。

准备 Web 运行时时，在独立 npm 项目中将 `@deepseek-ai/dsh` 钉到目标精确版本并保留 lockfile。rc.3 也可使用本机桌面包的原始运行时副本。alpha.2 测试使用 Node 24.22.3；桌面使用各自官方包的内置 Node。

通过该版 CLI 先初始化 `web` profile，再运行 `dsh plugin --profile web add <候选插件.tgz>`。测试真正的打包产物，不只链接开发目录。pnpm 必须可用；profile 的 `autoInstallPeers: false` 保持宿主提供共享依赖。安装后检查 profile 的依赖树，不能出现额外的 storage-domain 等核心服务副本。

## 重复执行

普通检查：

```powershell
npm run check
npm test
npm pack --pack-destination <仓库外的产物目录>
```

Web 验收（使用新的 evidence 目录）：

```powershell
node scripts/verify-host.mjs <runtime目录> <独立Home> <新的evidence目录> <browser-tools/package.json>
```

`browser-tools` 需要安装 `playwright-core`；默认使用 `C:/Program Files/Google/Chrome/Application/chrome.exe`，可通过 `DSH_TEST_CHROME` 指定其他 Chrome。脚本启动本地模拟模型，写入仅本次测试的 overlay，核对宿主核心服务，运行浏览器操作并留存截图，然后验证原生分支的卡片快照。模型回执只用于验证上下文传递，不代表真实模型风格效果。

验收脚本的 stdout/stderr 应保存为该 evidence 目录的 `web-fixture.log`，浏览器据此取得测试服务器地址。每次启动使用全新 evidence 目录，避免复用旧端口或日志。

独立进程重启验收：

```powershell
node scripts/verify-host.mjs <同一runtime> <同一Home> <新的重启evidence目录> <browser-tools/package.json> <上一轮evidence/restart-expectation.json>
```

检查原会话和分支绑定、历史开场白数量，以及被删除默认卡不会恢复。`host-result.json` 和 `restart-result.json` 分别记录结果。

日常手动查看独立 Web UI：

```powershell
./scripts/start-web.ps1 -Version 0.2.3-alpha.2 -Runtime <runtime目录> -HomeDirectory <独立Home> -NodeExecutable <对应node.exe>
```

脚本检查实际宿主版本并只在子命令期间设置 DSH_HOME，退出后恢复当前 PowerShell 的原值。

## 桌面验收

使用官方签名安装包，先核对官方 feed 的版本、大小、SHA-512 和 Windows 签名，再解包到独立目录，不执行安装器。`scripts/launch-desktop.mjs` 通过启动调试器在主入口执行前显式设置 userData/sessionData，之后执行官方未修改的主入口，并把核实的路径、版本和进程 ID 写入 `launch.json`。它保留真实 Electron Shell、Desktop Host、内置运行时和桌面鉴权。

```powershell
node scripts/launch-desktop.mjs <桌面exe> <独立Home> <独立userData> <桌面evidence> <仅本机CDP端口>
```

先启动一次以初始化 desktop profile，再退出该测试实例，通过它自己的 `resources/runtime/cli/bin/dsh.cmd plugin --profile desktop add <候选包>` 安装。npm CLI 不能代替桌面自带命令管理 desktop profile。

模拟模型仍需单独启动 `fixture-model.mjs`；其本地端口写入测试 profile 的 provider 配置。测试专用 `DSH_ROLEPLAY_FIXTURE_KEY=local-test-only` 是模拟标记，不是真实凭据。配置示例见 Web 验收生成的 `fixture.patch.yml`，不要拷贝日常设置。

桌面启动后设置 `DSH_TEST_CDP=http://127.0.0.1:<端口>` 和 `QYB_BROWSER_TOOLS=<browser-tools/package.json>`，运行 `node browser-check.mjs <桌面evidence>`，脚本连接已有的 `dsh-app://app/` 页面，复用同一套操作并保存截图。关闭 CDP 客户端不退出桌面程序；测试结束后退出或停止 launch.json 记录的测试进程，并关闭模拟模型。
